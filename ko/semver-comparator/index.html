Semver 비교기 & 검사기

요약하면: 버전 번호 두 개를 입력하고 각각이 유효한 semver인지, 어느 것이 더 새로운지, 간격이 major, minor, patch 단계인지 알아보세요.
🔒 설계상 비공개: 모든 것이 이 기기의 브라우저에서 실행돼요. 입력은 서버에 절대 업로드되지 않아요.

소개

의미론적 버전 관리(semver.org)는 버전 번호에 계약을 줘요: 파괴적 변경에는 MAJOR, 하위 호환 기능에는 MINOR, 하위 호환 수정에는 PATCH — 그리고 사전 릴리스 접미사(1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-beta < 1.0.0) and +build metadata that never affects precedence. The comparator implements the spec's precedence algorithm exactly, including the fiddly pre-release rules (numeric identifiers compare numerically and rank below alphanumeric ones; a version with a pre-release is older than the same version without). It is the check CI pipelines and package managers run millions of times a day.

자주 묻는 질문

1.0.0-alpha가 1.0.0보다 새로운가요?

아니요 — 사전 릴리스는 그 릴리스보다 오래됐어요: 1.0.0-alpha < 1.0.0. 패키지 관리자가 베타를 안전하게 제공할 수 있게 하는 규칙이에요.

+build 메타데이터가 중요한가요?

우선순위에는 해당하지 않아요: 1.0.0+exp와 1.0.0은 순서에서 동일하지만, 메타데이터는 정보를 위해 보존돼요.
