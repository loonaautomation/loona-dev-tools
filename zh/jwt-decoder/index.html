JWT 解码器 - 读取标头与负载，检查到期时间

简而言之： JWT 解码器将 JSON Web Token 分解为其标头和载荷，以可读的 JSON 显示这两者，并将到期时间和发布时间戳转换为通俗的日期。它不能——任何解码器都不能——证明令牌是真实的。

JWT 看起来像一长串无法读懂的字符串，但前两部分只是 Base64url 编码的 JSON。粘贴一个令牌，即可在调试时读取它声称的内容——它是给谁的、何时到期。仅将其用于检查；真正的信任需要在服务器上验证签名。

重要： 这个解码器会 不验证签名。它只读取令牌的内容。切勿仅凭解码后的 JWT 就信任它——任何人都能创建或篡改未经验证的令牌。务必始终在您的服务器上正确验证令牌。
按设计保证隐私： 这个工具中的一切都 100% 在您的浏览器中使用 JavaScript 完成。您的输入从不上传到服务器，从不存储，我们也从不见过它——关闭标签，一切都消失了。

如何使用 JWT 解码器

  1. 把完整的令牌（全部三个部分）粘贴到框中。
  2. 点击“解码令牌”。
  3. 阅读标头和负载，并检查过期行——然后在信任它之前，在您自己的系统中正确验证令牌。

它如何工作

JWT 是由点连接的三个 Base64url 字符串：header.payload.signature。header 指明签名算法；payload 携带诸如 sub（主题）、iat（签发时间）和 exp（到期时间，以秒为单位的 Unix 时间戳）等声明。本工具把前两部分从 Base64url 解码为 JSON——与您自己的代码所做的解码完全相同——并把数字时间声明转换为人类可读的日期。第三部分 signature 会显示为存在，但不会被检查：验证它需要密钥或公钥，必须在您的后端完成。

实例

解码那个经典的示例令牌会显示 header {"alg":"HS256","typ":"JWT"} 和一个带 sub "1234567890" 和 iat 1516239022 的 payload——本工具把它渲染为 "Thu, 18 Jan 2018 01:30:22 GMT"，这比原始数字容易理解得多。

常见问题

这个 JWT 解码器免费吗？

是的——免费，无需注册，没有限制。

本工具会验证令牌吗？

不会。它只负责解码。解码后的令牌对真实性什么也证明不了——任何人都能写任何负载并编码它。签名验证需要密钥，属于您的服务器。

为什么负载看起来可读？

JWT 的各部分是编码的，不是加密的。编码是为了传输，而不是保密——切勿把机密放进 JWT 负载中。

在这里粘贴真实的令牌安全吗？

您的令牌 100% 在您的浏览器中解码，从不上传。即便如此，好的做法是避免将实时生产令牌粘贴到任何工具中——使用形状相同的测试令牌。

"exp" 是什么意思？

令牌的过期时间，以秒为单位的 Unix 时间戳。本工具把它转换为可读的日期，并告诉您它是否已经过期。
