Em resumo: todos os códigos de estado que importam no desenvolvimento diário — o que cada um significa, quando é utilizado, e as armadilhas (401 vs 403, 302 vs 307) — filtrável enquanto escreve.

Sobre

Os códigos de estado são o resumo de um número do servidor de cada resposta, agrupados por classe: 1xx informativo, 2xx sucesso, 3xx redirecionamento, 4xx o cliente errou, 5xx o servidor errou. A tabela dá os códigos que os programadores em atividade realmente encontram, com as nuances que importam na prática — 401 significa não autenticado apesar do seu nome, 403 é uma recusa independentemente do início de sessão, 422 é a falha de validação da API, 429 exige recuo. Códigos não listados (a cauda longa de 1xx e códigos experimentais) são raros o suficiente para que só a classe lhe diga como tratá-los.

Perguntas Frequentes

Qual é a diferença entre 401 e 403?

401: não sabemos quem é (autentique-se). 403: sabemos, e mesmo assim não pode.

302 ou 307 para um redirecionamento temporário?

O 307 preserva o método e o corpo; o 302 historicamente permitia aos clientes mudar POST para GET. Trabalho novo deve utilizar 307 (ou 308 para permanente).
