TAR فائل کریئیٹر - اپنی فائلوں سے ایک .tar آرکائیو بنائیں

مختصراً: TAR فائل کریئیٹر فائلوں کے کسی سیٹ کو واحد معیاری .tar آرکائیو میں آپ کے براؤزر میں spec-درست ustar لکھنے والے سے بنڈل کرتا ہے - فائلیں شامل کریں، اختیاری طور پر انہیں فولڈر میں گروپ کریں، اور ڈاؤن لوڈ کریں۔

TAR اب بھی Linux, سرورز اور بیک اپس کی مشترکہ زبان ہے - لیکن Windows صارفین جنہیں tarball بنانا ہے عام طور پر پہلے کچھ انسٹال کرنا پڑتا ہے۔ یہ صفحہ آپ کے براؤزر میں اصل TAR آرکائیوز لکھتا ہے: درست ustar ہیڈرز، چیک سمز اور ٹائم اسٹیمپس، آپ کے آلے پر بنائے گئے بغیر کچھ اپ لوڈ کیے۔

فائلیں یہاں ڈالیں یا اپنے آلے سے فائلیں منتخب کرنے کے لیے کلک کریں
فائل نامسائز

یاد رکھیں: TAR کمپریس نہیں کرتا۔ .tar تقریباً تمام شامل فائلوں کے سائز کے برابر ہوگا (512-byte بلاکس تک round کیا گیا)۔ چھوٹا چاہیے؟ نتیجہ بعد میں GZIP کمپریسر سے گزاریں، یا اس کے بجائے ZIP فائل کریئیٹر استعمال کریں۔

ڈیزائن سے نجی: اس ٹول میں سب کچھ 100% آپ کے براؤزر میں JavaScript سے ہوتا ہے۔ آپ کی فائلیں کبھی سرور پر اپ لوڈ نہیں ہوتیں، کبھی محفوظ نہیں ہوتیں اور ہمارے دیکھنے میں نہیں آتیں - ٹیب بند کریں اور سب کچھ ختم۔ ایک ایماندار حد: تبدیلی آپ کے آلے کی میموری میں ہوتی ہے، لہٰذا بہت بڑے آرکائیوز (کئی سو میگا بائٹ) کم-میموری فون پر سست یا ناکام ہو سکتے ہیں۔

TAR فائل کریئیٹر کا استعمال کیسے کریں

  1. اپنی فائلیں اوپر والے خانے پر ڈالیں، یا اس پر کلک کریں اور اپنے آلے سے فائلیں منتخب کریں۔ آپ کئی مرحلوں میں فائلیں شامل کر سکتے ہیں۔
  2. فہرست دیکھیں - غلطی سے شامل شدہ کچھ بھی ہٹائیں، اور کل سائز پر نظر رکھیں۔
  3. اختیاری طور پر فولڈر نام لکھیں تاکہ ہر فائل آرکائیو میں ایک فولڈر کے اندر بیٹھے، اور TAR کو نام دیں۔
  4. TAR بنائیں اور ڈاؤن لوڈ کریں پر کلک کریں۔ .tar، Linux/macOS پر tar سے، اور Windows پر 7-Zip یا WinRAR سے کھلتا ہے۔

یہ کیسے کام کرتا ہے

ایک TAR آرکائیو ریکارڈز کی ایک اسٹریم ہے: ہر فائل کے لیے، ایک 512-byte ustar ہیڈر بلاک (فائل کا نام، آکٹل میں سائز، ترمیم کا وقت، خود ہیڈر کا چیک سم، 'ustar' جادو، اور ایک سابقہ فیلڈ جو راستوں کو 100 حروف سے لمبا چلنے دیتی ہے - اس سے بھی آگے کے راستوں کے لیے GNU longname اندراجات کے ساتھ)، جس کے بعد فائل کا مواد 512-byte بلاکس کی پوری تعداد تک بھرا ہوا۔ دو صفر بلاکس آرکائیو بند کرتے ہیں۔ یہ صفحہ اس فارمیٹ کو براہ راست نافذ کرتا ہے - کوئی لائبریری نہیں، کوئی سرور نہیں - اور مصنف کی تصدیق Python کے tarfile ماڈیول سے اس کی آؤٹ پٹ کو بائٹ بہ بائٹ واپس پڑھوا کر کی گئی۔ TAR فائلوں کو غیر کمپریس شدہ محفوظ کرتا ہے، لہٰذا آرکائیو اس کے حصوں کا مجموعہ ہے؛ کمپریشن ایک الگ مرحلہ ہے (یہی .tar.gz شامل کرتا ہے)۔

کام شدہ مثال

آپ تین فائلیں شامل کرتے ہیں: deploy.sh (1 KB), config.yml (3 KB) اور logo.png (48 KB)، فولڈر نام 'release' مقرر کے ساتھ۔ ٹول release.tar بناتا ہے - یا آپ کا منتخب نام - ایک release فولڈر رکھتے ہوئے تمام تین فائلوں کے ساتھ، ہر ایک اپنا اصل ترمیم وقت رکھتی ہوئی۔ 52 KB مواد پر TAR تقریباً 54 KB نکلتا ہے: خود فائلیں، تین ہیڈرز اور padding، بغیر کمپریشن - عین جو tar، Linux پر بنائے گا۔

کیا میری فائلیں کسی سرور پر اپ لوڈ ہوتی ہیں؟

نہیں۔ TAR آپ کے براؤزر میں چلنے والے JavaScript سے، آپ کے آلے پر لکھا جاتا ہے۔ آپ کی فائلیں اسے کبھی نہیں چھوڑتیں۔

TAR میری فائلوں جتنے سائز کا کیوں ہے - یا تھوڑا بڑا؟

TAR کچھ کمپریس نہیں کرتا؛ یہ صرف بنڈل کرتا ہے۔ ہر فائل ایک 512-byte ہیڈر بھی شامل کرتی ہے اور 512-byte حد تک padded ہے، لہٰذا آرکائیو خام کل سے تھوڑا بڑا ہے۔ ایک کمپریس شدہ tarball کے لیے، TAR یہاں بنائیں اور پھر اسے GZIP کمپریسر سے گزاریں - لفظی طور پر اسی طرح .tar.gz بنتا ہے۔

کیا Linux اور GNU tar یہاں بنائے گئے آرکائیوز قبول کریں گے؟

ہاں۔ لکھنے والا ustar تفصیلات کی پیروی کرتا ہے - درست آکٹل فیلڈز اور ہیڈر چیک سم، ustar جادو، لمبے راستوں کے لیے سابقہ تقسیم اور بہت لمبوں کے لیے GNU longname اندراجات - اور اس کی آؤٹ پٹ ٹیسٹنگ کے دوران Python کے tarfile ماڈیول سے واپس پڑھ کر تصدیق شدہ تھی۔

کیا میں موجودہ TAR میں فائلیں شامل کر سکتا ہوں یا براہ راست .tar.gz بنا سکتا ہوں؟

اس ٹول میں نہیں - یہ ہر بار ایک تازہ آرکائیو بناتا ہے۔ ایک موجودہ ZIP کو ایک مرحلے میں .tar.gz میں بدلنے کے لیے، ZIP سے TAR.GZ کنورٹر استعمال کریں؛ اس TAR کو .tar.gz میں کمپریس کرنے کے لیے، بعد میں GZIP کمپریسر استعمال کریں اور نتیجے کا نام .tar.gz رکھیں۔
