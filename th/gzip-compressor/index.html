ตัวบีบอัด GZIP - บีบไฟล์หนึ่งไฟล์เป็น .gz

สรุปสั้น ๆ: ตัวบีบอัด GZIP ย่อไฟล์เดี่ยวเป็น .gz โดยใช้กลไก gzip ที่สร้างไว้ในเบราว์เซอร์ของคุณ - ไม่มีการดาวน์โหลดไลบรารี ไม่มีการอัปโหลด - และแสดงให้คุณเห็นอย่างแม่นยำว่าคุณประหยัดพื้นที่ไปเท่าใด

Gzip คือม้างานด้านการบีบอัดของเว็บและของ Linux: ไฟล์ล็อก การส่งออก CSV ดัมป์ฐานข้อมูล และไฟล์บีบอัด TAR ล้วนหดลงอย่างมากภายใต้นี้ หน้านี้บีบอัดไฟล์หนึ่งไฟล์เป็น .gz ด้วย Compression Streams API ที่สร้างไว้ในเบราว์เซอร์สมัยใหม่ - เส้นทางที่เร็วที่สุดเท่าที่เป็นไปได้ และอยู่บนอุปกรณ์ของคุณทั้งหมด

วางไฟล์หนึ่งไฟล์ที่นี่ หรือคลิกเพื่อเลือกมันจากอุปกรณ์ของคุณ

Gzip บีบอัดไฟล์เดียว - มันไม่ใช่รูปแบบไฟล์บีบอัด หากต้องการบีบอัดหลายไฟล์เป็น .gz เดียว ให้รวมมัดพวกมันก่อนด้วย ตัวสร้างไฟล์ TAR, จากนั้นบีบอัด .tar (การรวมกันนั้นคือสิ่งที่ .tar.gz เป็นพอดี) หากต้องการเปลี่ยน .gz กลับเป็นไฟล์ต้นฉบับ ให้ใช้ ตัวแยกไฟล์ GZ.

เป็นส่วนตัวโดยการออกแบบ: ทุกอย่างในเครื่องมือนี้เกิดขึ้น 100% ในเบราว์เซอร์ของคุณด้วย JavaScript ไฟล์ของคุณไม่เคยถูกอัปโหลดไปยังเซิร์ฟเวอร์ ไม่เคยถูกจัดเก็บ และไม่เคยถูกเห็นโดยเรา - ปิดแท็บแล้วทุกอย่างหายไป ขีดจำกัดที่ซื่อตรงหนึ่งข้อ: การแปลงเกิดขึ้นในหน่วยความจำของอุปกรณ์ของคุณ ดังนั้นไฟล์บีบอัดที่ใหญ่มาก (หลายร้อยเมกะไบต์) อาจช้าหรือล้มเหลวบนโทรศัพท์ที่มีหน่วยความจำน้อย

วิธีใช้ ตัวบีบอัด GZIP

  1. วางไฟล์หนึ่งไฟล์ลงบนกล่องด้านบน หรือคลิกมันแล้วเลือกไฟล์จากอุปกรณ์ของคุณ
  2. คลิกบีบอัดเป็น .gz กลไก gzip ของเบราว์เซอร์ของคุณเองทำงานบนอุปกรณ์ของคุณ
  3. เปรียบเทียบขนาดในบทสรุป: ต้นฉบับ ที่บีบอัดแล้ว และเปอร์เซ็นต์ที่ประหยัดได้
  4. คลิกดาวน์โหลดเพื่อบันทึกไฟล์ .gz มันเปิดด้วย gzip, tar, 7-Zip, WinRAR - หรือ ตัวแยกไฟล์ GZ ของเรา

วิธีการทำงาน

Gzip ห่อหุ้มอัลกอริทึม DEFLATE (การจับคู่ LZ77 บวกการเข้ารหัส Huffman) ในคอนเทนเนอร์ขนาดเล็ก: ส่วนหัว 10 ไบต์ที่เริ่มต้นด้วยไบต์มหัศจรรย์ 1F 8B ข้อมูลที่บีบอัด และเช็กซัมบวกขนาดต้นฉบับเป็นส่วนท้าย หน้านี้ป้อนไฟล์ของคุณผ่าน CompressionStream API - การบีบอัด gzip ที่ใช้งานในตัวใน Chrome, Edge, Firefox และ Safari - ดังนั้นจึงไม่มีตัวบีบอัด JavaScript ให้ดาวน์โหลด และงานทำงานด้วยความเร็วเนทีฟ ไฟล์เข้าหนึ่งไฟล์ ไฟล์ออกหนึ่งไฟล์: gzip ไม่มีแนวคิดเรื่องโฟลเดอร์ ซึ่งเป็นเหตุผลว่าทำไมการจับคู่ .tar.gz แบบคลาสสิกจึงมีอยู่ - tar รวมมัด gzip บีบ

ตัวอย่างที่ทำแล้ว

คุณวาง access.log บันทึกเว็บเซิร์ฟเวอร์ขนาด 4.2 MB บันทึกเป็นข้อความที่ซ้ำซาก - ที่อยู่ การประทับเวลา และรหัสสถานะเดียวกันซ้ำแล้วซ้ำเล่า - ดังนั้น gzip จึงบดมันเหลือ 380 KB ประหยัด 91% และ access.log.gz พร้อมสำหรับจัดเก็บหรือส่งอีเมล วาง JPEG ขนาด 4.2 MB แทนและ .gz จะออกมาที่ 4.2 MB เช่นกัน: ข้อมูล JPEG ถูกบีบอัดแล้ว และหน้าบอกคุณอย่างนั้นอย่างซื่อตรงแทนที่จะแกล้งทำเป็นอย่างอื่น

คำถามที่พบบ่อย

ตัวบีบอัด GZIP นี้ฟรีหรือไม่?

ใช่ - ฟรี ไม่ต้องสมัครสมาชิก ไม่มีขีดจำกัดและไม่มีลายน้ำ

ไฟล์ของฉันถูกอัปโหลดไปยังเซิร์ฟเวอร์หรือไม่?

ไม่ การบีบอัดใช้กลไก gzip ที่สร้างไว้ในเบราว์เซอร์ของคุณ (Compression Streams API) ไฟล์ของคุณไม่เคยออกจากอุปกรณ์ของคุณ

ฉันบีบอัดหลายไฟล์เป็น .gz เดียวได้อย่างไร?

Gzip จัดการไฟล์เดียวพอดี รวมไฟล์เป็น .tar เดียวด้วย ตัวสร้างไฟล์ TAR ก่อน จากนั้นบีบอัด .tar นั้นที่นี่ - ผลลัพธ์คือ .tar.gz มาตรฐาน (เพียงเปลี่ยนชื่อ file.tar.gz หากจำเป็น)

ฉันเอาไฟล์ต้นฉบับกลับมาจาก .gz ได้อย่างไร?

ใช้ ตัวแยกไฟล์ GZ บนไซต์นี้ - มันย้อนกระบวนการในเบราว์เซอร์ของคุณ บน Linux และ macOS, gunzip file.gz ทำงานเดียวกัน

ทำไมไฟล์ของฉันจึงใหญ่ขึ้นเล็กน้อย?

รูปแบบที่บีบอัดมาแล้ว (JPG, PNG, MP4, PDF, ZIP) แทบไม่เหลือการซ้ำให้ gzip ใช้ประโยชน์ และตัวห่อ .gz เพิ่มส่วนหัวและเช็กซัมอีกไม่กี่ไบต์ สำหรับไฟล์เหล่านั้น การเพิ่มขึ้นเล็กน้อย - โดยปกติต่ำกว่า 1% มาก - เป็นเรื่องปกติและไม่เป็นอันตราย
