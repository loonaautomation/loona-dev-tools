JWT-Decoder - Header & Payload lesen, Ablauf prüfen

Kurz gesagt: das JWT-Decoder teilt ein JSON-Web-Token in seinen Header und seine Payload, zeigt beide als lesbares JSON und übersetzt die Ablauf- und Ausgestellt-um-Zeitstempel in einfache Daten. Er beweist nicht – und kein Decoder kann es – dass das Token echt ist.

Ein JWT sieht aus wie eine lange, unlesbare Zeichenfolge, aber die ersten beiden Teile sind nur Base64url-codiertes JSON. Fügen Sie ein Token ein, um beim Debuggen zu lesen, was es behauptet – für wen es gilt, wann es abläuft. Nutzen Sie es nur zur Inspektion; echtes Vertrauen erfordert die Signaturprüfung auf einem Server.

Wichtig: dieser Decoder tut die Signatur NICHT verifizieren. Es liest nur den Inhalt des Tokens. Vertrauen Sie einem decodierten JWT niemals allein – jeder kann ein ungeprüftes Token erstellen oder verändern. Validieren Sie Tokens immer ordnungsgemäß auf Ihrem Server.
Privat per Design: alles in diesem Tool geschieht zu 100 % in Ihrem Browser mit JavaScript. Ihre Eingabe wird niemals auf einen Server hochgeladen, niemals gespeichert und niemals von uns gesehen – schließen Sie den Tab und alles ist weg.

So verwenden Sie den JWT-Decoder

  1. Fügen Sie das vollständige Token (alle drei Teile) in das Feld ein.
  2. Klicken Sie auf „Token decodieren“.
  3. Lesen Sie Header und Payload und prüfen Sie die Ablaufzeile – verifizieren Sie das Token dann ordnungsgemäß in Ihrem eigenen System, bevor Sie ihm vertrauen.

So funktioniert es

Ein JWT besteht aus drei durch Punkte verbundenen Base64url-Zeichenfolgen: header.payload.signature. Der Header nennt den Signaturalgorithmus; die Payload trägt Claims wie sub (Subject), iat (Issued-at) und exp (Expiry, als Unix-Zeitstempel in Sekunden). Dieses Tool decodiert die ersten beiden Teile von Base64url zu JSON – genau dieselbe Decodierung, die Ihr eigener Code ausführt – und wandelt die numerischen Zeit-Claims in für Menschen lesbare Daten um. Der dritte Teil, die Signatur, wird als vorhanden angezeigt, aber NICHT geprüft: Ihre Prüfung braucht das Geheimnis oder den öffentlichen Schlüssel und muss in Ihrem Backend stattfinden.

Durchgerechnetes Beispiel

Die Decodierung des klassischen Beispiel-Tokens zeigt den Header {"alg":"HS256","typ":"JWT"} und eine Payload mit sub „1234567890“ und iat 1516239022 – was das Tool als „Thu, 18 Jan 2018 01:30:22 GMT“ rendert, weit leichter zu durchdenken als die rohe Zahl.

Häufig gestellte Fragen

Ist dieser JWT-Decoder kostenlos?

Ja – kostenlos, keine Registrierung, keine Limits.

Verifiziert dieses Tool das Token?

Nein. Es decodiert nur. Ein decodiertes Token beweist nichts über Authentizität – jeder kann jede beliebige Payload schreiben und codieren. Die Signaturverifizierung erfordert den Schlüssel und gehört auf Ihren Server.

Warum sieht die Payload überhaupt lesbar aus?

JWT-Teile sind codiert, nicht verschlüsselt. Codierung ist für den Transport, nicht für Geheimhaltung – legen Sie niemals Geheimnisse in eine JWT-Payload.

Ist es sicher, hier ein echtes Token einzufügen?

Ihr Token wird zu 100 % in Ihrem Browser decodiert und niemals hochgeladen. Trotzdem ist es gute Praxis, keine Live-Produktions-Tokens in irgendein Tool einzufügen – verwenden Sie ein Test-Token mit derselben Form.

Was bedeutet "exp"?

Die Ablaufzeit des Tokens als Unix-Zeitstempel in Sekunden. Dieses Tool wandelt sie in ein lesbares Datum um und sagt Ihnen, ob sie bereits abgelaufen ist.
