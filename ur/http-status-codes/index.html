HTTP اسٹیٹس کوڈز حوالہ

مختصراً: روزانہ ترقی میں اہم تمام اسٹیٹس کوڈز — ہر ایک کا مطلب کیا ہے، یہ کب استعمال ہوتا ہے، اور جال (401 بمقابلہ 403, 302 بمقابلہ 307) — جیسے آپ لکھتے ہیں فلٹر کے قابل۔
🔒 ڈیزائن سے نجی: اس آلے پر سب کچھ آپ کے براؤزر میں چلتا ہے۔ آپ کا ان پٹ کبھی سرور پر اپ لوڈ نہیں ہوتا۔

100جاری رکھیںکلائنٹ کو درخواست باڈی کے ساتھ جاری رکھنا چاہیے
101پروٹوکولز بدلناپروٹوکول اپ گریڈ قبول (مثلاً WebSocket پر)
200OKدرخواست کامیاب ہوئی — ڈیفالٹ کامیابی جواب
201بنایا گیاایک نیا وسیلہ بنایا گیا (عام POST کامیابی)
202قبول شدہasync پروسیسنگ کے لیے قطار میں، ابھی مکمل نہیں
204کوئی مواد نہیںجان بوجھ کر خالی باڈی کے ساتھ کامیابی
301مستقل منتقلوسیلے کا نیا مستقل URL ہے — لنکس اپ ڈیٹ کریں؛ SEO ایکویٹی منتقل ہوتی ہے
302ملاعارضی ری ڈائریکٹ (تاریخی طور پر غلط استعمال؛ 303/307 دیکھیں)

304ترمیم نہیں ہوئیکیش شدہ کاپی اب بھی درست ہے — ETag/Last-Modified کے ذریعے دوبارہ توثیق کریں

403ممنوعہتصدیق شدہ ہو یا نہ ہو، رسائی مسترد ہے

414URI بہت لمباURL سرور حدوں سے بڑھ گیا
415غیر حمایت یافتہ میڈیا قسمدرخواست Content-Type حمایت یافتہ نہیں

422ناقابل پروسیس موادSyntax ٹھیک ہے لیکن سیمینٹکس توثیق ناکام (APIs کو یہ پسند ہے)
425بہت جلدیسرور ممکنہ-دوبارہ چلائی گئی درخواست پروسیس کرنے کو تیار نہیں
429بہت زیادہ درخواستیںشرح حد آ گئی — پیچھے ہٹیں، Retry-After کا احترام کریں

504Gateway Timeoutپراکسی/گیٹ وے اپ اسٹریم کے انتظار میں ٹائم آؤٹ ہو گیا

بارے میں

اسٹیٹس کوڈز ہر جواب کا سرور کا ایک-عدد خلاصہ ہیں، کلاس کے لحاظ سے گروپ شدہ: 1xx معلوماتی، 2xx کامیابی، 3xx ری ڈائریکشن، 4xx کلائنٹ نے غلطی کی، 5xx سرور نے غلطی کی۔ ٹیبل وہ کوڈز دیتی ہے جن سے کام کرنے والے ڈویلپرز اصل میں ملتے ہیں، ان باریکیوں کے ساتھ جو عملی طور پر اہم ہیں — 401 کا مطلب اس کے نام کے باوجود غیر تصدیق شدہ ہے، 403 لاگ ان سے قطع نظر انکار ہے، 422 API توثیق ناکامی ہے، 429 پسپائی مانگتا ہے۔ درج نہ کوڈز (1xx اور تجرباتی کوڈز کی لمبی دم) اتنے نایاب ہیں کہ صرف کلاس ہی آپ کو بتاتی ہے کہ انہیں کیسے سنبھالیں۔

اکثر پوچھے گئے سوالات

401 اور 403 کے درمیان فرق کیا ہے؟

401: ہمیں نہیں معلوم کہ آپ کون ہیں (تصدیق کریں)۔ 403: ہمیں معلوم ہے، اور پھر بھی آپ کو اجازت نہیں۔

عارضی ری ڈائریکٹ کے لیے 302 یا 307؟

307 طریقہ اور باڈی برقرار رکھتا ہے؛ 302 تاریخی طور پر کلائنٹس کو POST سے GET پر جانے دیتا تھا۔ نئے کام میں 307 استعمال کرنا چاہیے (یا مستقل کے لیے 308)۔
