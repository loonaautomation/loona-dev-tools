SQL فارمیٹر - پڑھنے کے قابل سوالات، ایک Clause فی لائن

مختصراً: SQL فارمیٹر کلیدی الفاظ بڑے حروف کرتا ہے، ہر بڑا clause (SELECT, FROM, WHERE, GROUP BY, ORDER BY, LIMIT اور ہر JOIN) اپنی لائن پر رکھتا ہے، اور AND / OR شرائط indent کرتا ہے - جبکہ اسٹرنگ literals عین لکھے گئے چھوڑتا ہے۔

پانچ جوائنز والی ایک لائن کی query تکنیکی طور پر درست اور عملی طور پر ناقابل مطالعہ ہے۔ اسے نیچے پیسٹ کریں اور وہی query اس ترتیب میں واپس پائیں جو آپ اچھے دن میں ہاتھ سے لکھتے۔

ڈیزائن سے نجی: اس ٹول میں سب کچھ 100% آپ کے براؤزر میں JavaScript سے ہوتا ہے۔ آپ کا ان پٹ کبھی سرور پر اپ لوڈ نہیں ہوتا، کبھی محفوظ نہیں ہوتا اور ہمارے دیکھنے میں نہیں آتا - ٹیب بند کریں اور سب کچھ ختم۔

SQL فارمیٹر کا استعمال کیسے کریں

  1. اپنی SQL query اوپر والے باکس میں پیسٹ کریں۔
  2. 'بڑے حروف کلیدی الفاظ' پر نشان رہنے دیں کلاسیکی شکل کے لیے، یا اسے ہٹائیں تاکہ آپ کا اصل کلیدی لفظ کیس برقرار رہے۔
  3. SQL فارمیٹ کریں پر کلک کریں۔
  4. فارمیٹ شدہ query کاپی کریں یا اسے .sql فائل کے طور پر ڈاؤن لوڈ کریں۔

یہ کیسے کام کرتا ہے

فارمیٹر پہلے آپ کے سوال کو ٹوکنز میں تقسیم کرتا ہے، لہٰذا کوٹ شدہ اسٹرنگز، دوہرے-کوٹ شدہ اور back-کوٹ شدہ شناخت کنندگان اچھوتے لے جائے جاتے ہیں - ایک لفظی جیسے 'select me' کبھی بڑے حروف یا تقسیم نہیں ہوتا۔ پھر یہ ٹوکن دھارے پر چلتا ہے کثیر-لفظ clauses پہچانتے ہوئے جیسے GROUP BY, ORDER BY اور LEFT OUTER JOIN, ہر بڑا clause تازہ لائن پر شروع کرتا ہے، اور AND اور OR شرائط ان کی اپنی indented لائنوں پر رکھتا ہے۔ آپریٹرز اور کاما کے ارد گرد اسپیسنگ روایتی واحد اسپیس تک معمول بنائی جاتی ہے۔

کام شدہ مثال

ایک-لائنر select id, name from users where age > 18 and city = 'New York' order by name limit 10 چھ صاف لائنیں بن جاتا ہے - SELECT, FROM, WHERE, ایک indented AND, ORDER BY اور LIMIT - جائزے یا ٹکٹ میں پیسٹ کے لیے تیار۔

اکثر پوچھے گئے سوالات

کیا یہ SQL فارمیٹر مفت ہے؟

ہاں - مکمل مفت، بغیر سائن اپ، بغیر سائز حد اور بغیر یومیہ حد۔

یہ کون سی SQL جدلیاں حمایت کرتا ہے؟

فارمیٹر clause ساخت پر کام کرتا ہے، جدلی قواعد پر نہیں، لہٰذا MySQL, PostgreSQL, SQL Server, SQLite اور دیگر سے معیاری SQL سب ایک ہی طرح فارمیٹ ہوتا ہے۔ یہ صرف لے آؤٹ خوبصورت بناتا ہے - یہ توثیق نہیں کرتا کہ آپ کا سوال چلے گا۔

کیا یہ ذیلی queries کو دوبارہ indent کرتا ہے؟

نہیں - قوسین والے subqueries اسی لائن پر رہتے ہیں جہاں وہ ظاہر ہوتے ہیں۔ گہری subquery indentation وہ جگہ ہے جہاں فارمیٹرز اکثر غلط اندازہ لگاتے ہیں، لہٰذا یہ ٹول clause-سطح لے آؤٹ پر رہتا ہے اور ایمانداری سے کہتا ہے۔

کیا میری اسٹرنگ لٹریلز محفوظ ہیں؟

ہاں۔ واحد-کوٹ شدہ اسٹرنگز (بشمول دوہرے-کوٹ escapes)، دوہرے-کوٹ شدہ اور back-کوٹ شدہ شناخت کنندگان بائٹ-بہ-بائٹ گزرتے ہیں؛ صرف ان سے باہر کلیدی الفاظ بڑے حروف ہوتے ہیں۔

کیا میرا SQL کسی سرور پر اپ لوڈ ہوتا ہے؟

نہیں۔ فارمیٹنگ 100% آپ کے براؤزر میں ہوتی ہے۔ آپ کے سوالات - اسکیما ناموں سمیت - آپ کے آلے سے کبھی نہیں نکلتے۔
