Převodník JSON na INI

Stručně: proměňte objekt JSON na soubor INI: skalární hodnoty nahoře, každý vnořený objekt se stane [section] — tvar, který parsery INI očekávají.
🔒 Soukromé už designem: vše běží ve vašem prohlížeči na tomto zařízení. Váš vstup se nikdy nenahrává na server.

Příklad

Vstup:

{"debug": true, "database": {"host": "localhost", "port": 5432}}

Výstup:

debug = true

[database]
host = localhost
port = 5432

O tomto převodníku

INI je ploché designem, takže mapování JSON je strukturální: řetězce, čísla a booleovské hodnoty nejvyšší úrovně se stanou holými řádky key = value (které podle konvence INI musí přijít před jakoukoli sekcí) a každý objekt nejvyšší úrovně se stane [sekcí] obsahující jeho skaláry. Pole a hlubší vnoření nemají poctivou reprezentaci v INI — místo aby nějakou vymýšlel, převodník je vynechá ze sekcí, které nemůže reprezentovat, a poznámka O aplikaci to říká: pokud je váš JSON hluboce vnořený, INI je prostě špatný cílový formát a YAML nebo TOML vám poslouží lépe. Hodnoty obsahující ; nebo # jsou v uvozovkách, aby znaky komentářů přežily cestu tam a zpět.

Často kladené otázky

Kam zmizelo pole mého vnořeného objektu?

INI nemůže vyjádřit pole; převodník vynechá to, co nemůže reprezentovat, místo aby to poškodil. Pro konfiguraci přívětivou k polím použijte TOML.

Může výstup číst configparser v Pythonu?

Ano — výstup následuje běžný dialekt, který čte configparser, se sekcemi a páry klíč = hodnota.
