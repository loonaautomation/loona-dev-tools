HTTP Status Codes Reference

संक्षेप में: सभी status codes जो daily development में मायने रखते हैं — हर एक का अर्थ, कब उपयोग होता है, और traps (401 vs 403, 302 vs 307) — जैसे आप type करते हैं filterable।
🔒 Design से निजी: सब कुछ इस device पर आपके browser में चलता है। आपका input कभी server पर upload नहीं होता।

हमारे बारे में

Status codes हर response का server का one-number summary हैं, class के अनुसार grouped: 1xx informational, 2xx success, 3xx redirection, 4xx client ने ग़लती की, 5xx server ने ग़लती की। Table वे codes देती है जिनसे working developers सच में मिलते हैं, उन nuances के साथ जो practice में मायने रखती हैं — 401 का अर्थ इसके नाम के बावजूद unauthenticated है, 403 login के बावजूद एक इनकार है, 422 API validation failure है, 429 backoff माँगता है। Listed नहीं किए गए codes (1xx और experimental codes की लंबी tail) इतने rare हैं कि सिर्फ़ class आपको बताती है कि उन्हें कैसे handle करें।

अक्सर पूछे जाने वाले सवाल

401 और 403 के बीच क्या अंतर है?

401: हमें नहीं पता कि आप कौन हैं (authenticate करें)। 403: हम जानते हैं, और फिर भी आपको अनुमति नहीं है।

अस्थायी redirect के लिए 302 या 307?

307 method और body को सुरक्षित रखता है; 302 ऐतिहासिक रूप से clients को POST से GET पर switch करने देता था। नए काम में 307 उपयोग करना चाहिए (या permanent के लिए 308)।
