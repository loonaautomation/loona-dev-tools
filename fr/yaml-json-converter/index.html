Convertisseur YAML ⇄ JSON - Pour les fichiers de configuration quotidiens

En bref : le Convertisseur YAML ⇄ JSON traduit le sous-ensemble YAML qui couvre presque chaque fichier de configuration réel - paires clé : valeur, mappages imbriqués par indentation, listes avec tirets, et scalaires chaînes, nombres, booléens et null - dans les deux directions, et vous dit franchement ce qu’il ne prend pas en charge.

Les fichiers de configuration vivent en YAML ; les API et le code vivent en JSON. Collez l’un ou l’autre ci-dessous pour obtenir l’autre - avec un analyseur de sous-ensemble honnête qui gère les constructions que les configurations réelles utilisent réellement.

Privé par conception : tout dans cet outil se passe à 100 % dans votre navigateur avec JavaScript. Votre entrée n’est jamais téléversée sur un serveur, jamais stockée et jamais vue par nous - fermez l’onglet et tout a disparu.

Comment utiliser le Convertisseur YAML vers JSON

  1. Collez le YAML ou le JSON dans la boîte du haut.
  2. Cliquez sur YAML → JSON ou JSON → YAML selon votre entrée.
  3. Examinez le résultat - l’entrée YAML devient du JSON embellie ; l’entrée JSON devient du YAML propre en style de blocs.
  4. Copiez le résultat ou téléchargez-le.

Comment ça fonctionne

Le lecteur YAML fonctionne en deux passages : il normalise d’abord votre document en lignes avec leur indentation (en retirant les commentaires hors guillemets), puis analyse récursivement les blocs - une suite de lignes à la même indentation est une liste si les lignes commencent par un tiret, une carte si elles portent des clés, ou un seul scalaire. Les clés sans valeur sur la même ligne prennent le bloc plus profondément indenté qui suit comme leur valeur. Les scalaires sont typés à la manière YAML : le texte entre guillemets reste une chaîne, true/false deviennent des booléens, null et ~ deviennent null, et les nombres simples deviennent des nombres JSON. L’écrivain dans l’autre direction émet le même sous-ensemble : indentation de deux espaces, tirets pour les listes, et guillemets uniquement là où une chaîne serait sinon mal lue.

Exemple travaillé

Un fragment de style docker-compose - un nom de service, une image, une liste de deux ports - se convertit en un objet JSON avec une carte imbriquée et un vrai tableau, et la reconversion directe de ce JSON rend le même YAML, ce qui est exactement l’aller-retour que la suite de tests vérifie.

Questions fréquemment posées

Ce convertisseur YAML vers JSON est-il gratuit ?

Oui - entièrement gratuit, sans inscription, sans limite de taille et sans plafond quotidien.

Quelles fonctions YAML sont prises en charge ?

Le sous-ensemble quotidien : cartes imbriquées par indentation, listes avec tirets (y compris les listes de cartes), scalaires cités et simples, nombres, booléens, null, et commentaires. Cela couvre la grande majorité des fichiers de configuration écrits à la main.

Quelles fonctions YAML ne sont PAS prises en charge ?

Les ancres et alias (&a / *a), les scalaires de bloc multilignes (| et >), le style de flux ({a: 1} / [1, 2]), les balises, et les fichiers multi-documents (---) ne sont pas analysés. Si votre fichier les utilise, convertissez avec une bibliothèque YAML complète - nous préférons le dire plutôt que de produire une conversion erronée.

JSON → YAML met-il les chaînes entre guillemets ?

Seulement lorsque c’est nécessaire : une chaîne qui ressemble à un nombre ou à un booléen, qui est vide, ou qui contient des caractères comme un deux-points suivi d’une espace est mise entre guillemets doubles afin qu’elle se relise comme la même chaîne.

Mes données sont-elles téléversées vers un serveur ?

Non. La conversion se passe à 100 % dans votre navigateur. Vos fichiers de configuration ne quittent jamais votre appareil.
