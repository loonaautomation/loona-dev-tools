YAML ⇄ JSON変換ツール - 日常の設定ファイルのために

要するに： YAML ⇄ JSON変換ツールは、ほとんどすべての実際の設定ファイルをカバーするYAMLサブセットを翻訳します。key: value ペア、インデントによるネストしたマップ、ダッシュ付きリスト、文字列、数値、ブール値、nullのスカラーです。両方向で、何をサポートしないかを率直に伝えます。

設定ファイルはYAMLに住み、APIとコードはJSONに住みます。どちらか一方を下に貼り付ければ、もう一方が得られます — 実世界の設定が実際に使う構造を処理する、正直なサブセットパーサー付きで。

設計上プライベート： このツールのすべては、JavaScriptを使ってブラウザで100%行われます。あなたの入力はサーバーにアップロードされることは決してなく、保存されることも、私たちに見られることもありません。タブを閉じるとすべてが消えます。

YAML→JSON変換ツールの使い方

  1. YAMLまたはJSONを上のボックスに貼り付けてください。
  2. 入力に応じて「YAML → JSON」または「JSON → YAML」をクリックしてください。
  3. 結果を確認してください。YAML入力は整形表示されたJSONに、JSON入力はきれいなブロック形式のYAMLになります。
  4. 結果をコピーするか、ダウンロードしてください。

仕組み

YAMLリーダーは二つのパスで動作します。まずドキュメントをインデント付きの行に正規化し（引用符の外のコメントを取り除きます）、次にブロックを再帰的に解析します。同じインデントの一連の行は、行がダッシュで始まればリスト、キーを持てばマップ、そうでなければ単一のスカラーです。同じ行に値のないキーは、続くより深くインデントされたブロックを値として取ります。スカラーはYAMLの方法で型付けされます。引用されたテキストは文字列のまま、true/falseはブール値に、nullと ~ はnullに、通常の数値はJSON数値になります。逆方向のライターは同じサブセットを出力します。二スペースのインデント、リストにはダッシュ、そして文字列が誤読される場合にのみ引用符です。

実例

docker-composeスタイルのフラグメント — サービス名、イメージ、二つのポートのリスト — は、ネストしたマップと本物の配列を持つJSONオブジェクトに変換され、そのJSONをそのまま変換して戻すと同じYAMLが返ります。これはまさに、テストスイートがチェックする往復変換です。

よくある質問

このYAML→JSON変換ツールは無料ですか？

はい - 完全に無料、登録不要で、サイズ制限も毎日の上限もありません。

サポートされているYAML機能はどれですか？

日常のサブセット：インデントによるネストしたマップ、ダッシュ付きリスト（マップのリストを含む）、引用されたスカラーと通常のスカラー、数値、ブール値、null、コメントです。これは手書きの設定ファイルの大部分をカバーします。

サポートされていないYAML機能はどれですか？

アンカーとエイリアス（&a / *a）、複数行のブロックスカラー（| と >）、フロースタイル（{a: 1} / [1, 2]）、タグ、複数ドキュメントファイル（---）は解析されません。あなたのファイルがそれらを使っている場合は、代わりに完全なYAMLライブラリで変換してください。間違った変換を出すより、その旨をお伝えする方がましだと考えます。

JSON → YAML は文字列をクォートしますか？

必要な場合のみです。数値やブール値のように見える文字列、空の文字列、コロンの後にスペースが続くような文字を含む文字列は、同じ文字列として読み戻せるよう二重引用符で囲まれます。

私のデータはサーバーにアップロードされますか？

いいえ。変換はブラウザで100%行われます。設定ファイルがデバイスから出ることは決してありません。
