소개

상태 코드는 모든 응답에 대한 서버의 한 숫자 요약으로, 클래스별로 그룹화돼요: 1xx 정보, 2xx 성공, 3xx 리디렉션, 4xx 클라이언트 오류, 5xx 서버 오류예요. 표는 일하는 개발자가 실제로 만나는 코드를, 실제로 중요한 뉘앙스와 함께 제공해요 — 401은 이름과 달리 인증되지 않음을 뜻하고, 403은 로그인과 관계없이 거부이며, 422는 API 검증 실패, 429는 후퇴를 요구해요. 나열되지 않은 코드(1xx와 실험 코드의 긴 꼬리)는 충분히 드물어 클래스만으로 처리 방법을 알 수 있어요.

자주 묻는 질문

401과 403의 차이는 무엇인가요?

401: 여러분이 누구인지 모릅니다(인증하세요). 403: 알고 있지만, 그래도 안 돼요.

임시 리디렉션에는 302와 307 중 무엇을 쓸까요?

307은 메서드와 본문을 보존해요; 302는 역사적으로 클라이언트가 POST를 GET으로 바꾸는 것을 허용했어요. 새 작업에는 307을(영구적인 경우 308을) 사용해야 해요.
