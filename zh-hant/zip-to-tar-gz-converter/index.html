ZIP 轉 TAR.GZ 轉換器 - 將 .zip 變成 .tar.gz Tarball

簡而言之： ZIP 轉 TAR.GZ 轉換器將 ZIP 歸檔重新打包為一個適當的 ustar tarball 並用 gzip 壓縮它，在您自己的裝置上完成——生成 Linux 世界執行的 .tar.gz 格式。

部署到 Linux 伺服器、餵給 Docker 構建，或把檔案交給一個期望 tarball 的工具？ZIP 在那個世界裡是個異類——.tar.gz 才是母語。本轉換器在瀏覽器中讀取您的 ZIP，寫出符合規範的 TAR 歸檔並用 gzip 壓縮它，全程不上傳任何東西。

如何使用 ZIP 轉 TAR.GZ 轉換器

  1. 把您的 .zip 檔案拖到上面的框中，或點選它從您的裝置中選擇檔案。
  2. 點選“轉換為 TAR.GZ”。ZIP 在您的裝置上被讀取，一個帶相同路徑的 TAR 歸檔被寫出，gzip 對它進行壓縮。
  3. 檢視摘要：轉換的檔案數和新 tarball 的大小。
  4. 點選“下載”儲存 .tar.gz 檔案——tar -xzf 能在任何 Linux 或 macOS 系統上開啟它。

它如何工作

本頁用 JSZip 讀取 ZIP，然後使用頁面內建的規範正確的 ustar 寫入器把內容寫出為 TAR 歸檔：每個檔案得到一個 512 位元組的標頭塊（名稱、大小、模式、校驗和，以及用於長路徑的字首欄位——對於連這都太長的路徑，使用 GNU 長名稱條目），其內容填充到 512 位元組邊界，並用兩個零塊關閉歸檔。完成的 TAR 用您瀏覽器內建的 gzip 引擎（Compression Streams API）壓縮。在測試期間，輸出針對 Python 的 tarfile 模組和 GNU tar 約定進行了驗證——它是一個真正的 tar 包，而不是改了名的 ZIP。

例項

您有 site-assets.zip（12 MB，240 個檔案）要上傳到一臺 Linux VPS，其部署指令碼執行 tar -xzf。在這裡轉換後，您將得到 site-assets.tar.gz（11.6 MB），同樣的 240 個檔案位於相同的路徑，並保留其 ZIP 時間戳。伺服器解壓它，就像這個 tarball 是在 Linux 上建立的一樣。

常見問題

這個 ZIP 轉 TAR.GZ 轉換器免費嗎？

是的——免費，無需註冊，沒有限制，也沒有水印。

我的檔案會被上傳到伺服器嗎？

不會。JSZip 讀取 ZIP，TAR 由本頁中的程式碼寫出，gzip 由您瀏覽器內建的引擎完成。一切都保留在您的裝置上。

GNU tar 和 Linux 工具會接受輸出嗎？

是的。TAR 寫入器遵循 ustar 規範——正確的標頭校驗和、八進位制大小欄位、長路徑的 ustar 字首拆分，以及當路徑甚至超過這個長度時的 GNU 長名稱條目——並且結果已透過使用 Python 的 tarfile 模組讀回進行了測試驗證。

檔案的時間戳和許可權會被保留嗎？

儲存在 ZIP 中的時間戳被帶到 TAR 標頭中。許可權被寫成標準預設值（檔案 0644，資料夾 0755），因為 ZIP 不能可靠地儲存 Unix 許可權——如果您需要確切的模式，在解壓後用 chmod 設定它們。

為什麼不改為轉換為普通的 .tar？

普通的 TAR 是未壓縮的，所以它大約是所有檔案加在一起的大小。.tar.gz 是 Linux 工具所期望的，其大小與 ZIP 接近。對於散裝檔案的普通 TAR，請使用 TAR 檔案建立工具。
