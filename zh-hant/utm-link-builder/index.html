UTM 連結構建器 - 分析能讀懂的活動 URL

簡而言之： UTM 連結構建器將 utm_source、utm_medium、utm_campaign 以及可選的 term/content 引數以正確的百分號編碼附加到任何 URL 上，保留 URL 上已有的查詢引數，並在您的瀏覽器中保留一個小型的歷史記錄。

未標記的活動連結在分析中都顯示為“直接”。在這裡正確標記它們——編碼已處理、現有引數保留、您最近的連結在本地儲存。

已儲存歷史（僅此瀏覽器）

按設計保證隱私： 這個工具中的一切都 100% 在您的瀏覽器中使用 JavaScript 完成。您的輸入從不上傳到伺服器，從不儲存，我們也從不見過它——關閉標籤，一切都消失了。

如何使用 UTM 連結構建器

  1. 貼上您落地頁的基礎 URL。
  2. 填寫 source（來自哪裡）、medium（什麼型別的連結）和 campaign（哪次推廣）——三個標準欄位。
  3. 只有當您需要區分同一活動中的兩個連結時，才新增 term 或 content。
  4. 點選“構建”，複製帶標籤的 URL，並在您的帖子、廣告或電子郵件中使用它。

它如何工作

構建器使用瀏覽器的標準 URL 解析器，所以編碼完全正確：空格變成 %20（或按 URLSearchParams 規則在查詢值中變成 +），值內部的和號永遠無法拆分成假引數，基礎 URL 上已有的任何查詢字串——比如 ?ref=nav 會被保留，同一鍵已有的 utm_ 值會被替換而不是重複新增。#fragment 按照 URL 的要求保留在最末尾、引數之後。歷史記錄僅儲存在您瀏覽器的 localStorage 中（最近 20 條連結），從不傳送到任何地方。

命名提示

選擇一個約定並永遠不要改變它：小寫、用連字元代替空格、每次都使用相同的來源名稱（facebook，而不是 FB 或 Facebook）——分析把每種拼寫都當作不同的來源。

常見問題

這個構建器免費嗎？

是的——完全免費，無需註冊。

哪些 UTM 欄位是必需的？

按慣例：source、medium 和 campaign。Term（付費關鍵詞）和 content（區分兩個創意）是可選的。

我的 URL 上已有的引數會怎樣？

它們被保留。如果 URL 已經有 utm_source，新值會替換它而不是重複該引數。

歷史儲存在哪裡？

只在您自己的瀏覽器中（localStorage），最多 20 條連結。清除它或切換瀏覽器會將它刪除。

我應該在內部連結上使用 UTM 標籤嗎？

不會——在您自己網站內部給連結打標籤，會覆蓋分析中的原始會話來源。UTM 用於來自外部的入站連結。
