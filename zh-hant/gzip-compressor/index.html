GZIP 壓縮工具 - 把一個檔案擠壓成 .gz

簡而言之： GZIP 壓縮工具使用瀏覽器內建的 gzip 引擎將單個檔案縮小為 .gz——無需下載庫，無需上傳——並確切顯示您節省了多少空間。

Gzip 是 Web 和 Linux 的壓縮主力：日誌檔案、CSV 匯出、資料庫轉儲和 TAR 歸檔在它下面都會大幅縮小。本頁使用現代瀏覽器內建的 Compression Streams API 把一個檔案壓縮成 .gz——這是最快的路徑，完全在您的裝置上完成。

Gzip 壓縮的是一個檔案——它不是歸檔格式。要把幾個檔案壓縮成一個 .gz，請先用 TAR 檔案建立工具，然後壓縮 .tar（這一組合正是 .tar.gz 的構成）。要把 .gz 還原為原始檔案，請使用 GZ 檔案解壓工具.

按設計保證隱私： 這個工具中的一切都 100% 在您的瀏覽器中使用 JavaScript 完成。您的檔案從不上傳到伺服器，從不儲存，我們也從不見過它——關閉標籤，一切都消失了。一個誠實的限制：轉換在您裝置的記憶體中進行，所以非常大的歸檔（數百兆位元組）在記憶體不足的手機上可能會很慢或失敗。

如何使用 GZIP 壓縮工具

  1. 把一個檔案拖到上面的框中，或點選它從您的裝置中選擇檔案。
  2. 點選“壓縮為 .gz”。您瀏覽器自己的 gzip 引擎在您的裝置上完成工作。
  3. 對比摘要中的大小：原始大小、壓縮後大小和節省的百分比。
  4. 點選“下載”儲存 .gz 檔案。它可以用 gzip、tar、7-Zip、WinRAR 開啟——或者用我們的 GZ 檔案解壓工具。

它如何工作

Gzip 把 DEFLATE 演算法（LZ77 匹配加 Huffman 編碼）包裹在一個小容器中：一個以魔術位元組 1F 8B 開頭的 10 位元組標頭、壓縮資料，以及作為尾部的校驗和加上原始大小。本頁把您的檔案送入 CompressionStream API——在 Chrome、Edge、Firefox 和 Safari 中原生實現的 gzip 壓縮——所以不需要下載 JavaScript 壓縮器，工作以原生速度執行。一個檔案進，一個檔案出：gzip 沒有資料夾的概念，這正是經典 .tar.gz 配對存在的原因——tar 捆綁，gzip 擠壓。

例項

您放入 access.log，一個 4.2 MB 的 Web 伺服器日誌。日誌是重複的文字——相同的地址、時間戳和狀態碼一遍又一遍——所以 gzip 將其壓縮到 380 KB，節省了 91%，access.log.gz 已準備好歸檔或透過電子郵件傳送。換成放入一個 4.2 MB 的 JPEG，.gz 也是 4.2 MB：JPEG 資料已經是壓縮過的，頁面會誠實地告訴您這一點，而不是假裝不是這樣。

常見問題

這個 GZIP 壓縮工具免費嗎？

是的——免費，無需註冊，沒有限制，也沒有水印。

我的檔案會被上傳到伺服器嗎？

不會。壓縮使用您瀏覽器內建的 gzip 引擎（Compression Streams API）。您的檔案從不離開您的裝置。

我如何把幾個檔案壓縮成一個 .gz？

Gzip 恰好處理一個檔案。先用 TAR 檔案建立工具把檔案捆綁成一個單獨的 .tar，然後在這裡壓縮那個 .tar——結果是一個標準的 .tar.gz（如有需要，改名為 file.tar.gz 即可）。

我如何從 .gz 取回我的原始檔案？

使用本站的 GZ 檔案解壓工具——它在您的瀏覽器中反轉這一過程。在 Linux 和 macOS 上，gunzip file.gz 做同樣的工作。

為什麼我的檔案變大了一點？

已經壓縮過的格式（JPG、PNG、MP4、PDF、ZIP）幾乎不留下可供 gzip 利用的重複內容，而 .gz 包裝會新增幾個位元組的標頭和校驗和。對於這些檔案，微小的增加——通常遠低於 1%——是正常且無害的。
