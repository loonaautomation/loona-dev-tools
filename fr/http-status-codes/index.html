Référence des codes d’état HTTP

En bref : tous les codes d’état qui comptent dans le développement quotidien — ce que chacun signifie, quand il est utilisé, et les pièges (401 contre 403, 302 contre 307) — filtrables pendant que vous saisissez.
🔒 Privé par conception : tout s’exécute dans votre navigateur sur cet appareil. Votre entrée n’est jamais téléversée sur un serveur.

À propos

Les codes d’état sont le résumé en un nombre du serveur pour chaque réponse, groupés par classe : 1xx informationnel, 2xx succès, 3xx redirection, 4xx le client a erré, 5xx le serveur a erré. Le tableau donne les codes que les développeurs en activité rencontrent réellement, avec les nuances qui comptent en pratique — 401 signifie non authentifié malgré son nom, 403 est un refus quel que soit l’état de connexion, 422 est l’échec de validation d’API, 429 exige un recul. Les codes non listés (la longue traîne des 1xx et des codes expérimentaux) sont assez rares pour que la classe seule vous dise comment les gérer.

Questions fréquemment posées

Quelle est la différence entre 401 et 403 ?

401 : nous ne savons pas qui vous êtes (authentifiez-vous). 403 : nous le savons, et vous n’avez quand même pas le droit.

302 ou 307 pour une redirection temporaire ?

307 préserve la méthode et le corps ; 302 laissait historiquement les clients passer de POST à GET. Les travaux nouveaux devraient utiliser 307 (ou 308 pour le permanent).
