Text în secvențe de escape Unicode

Pe scurt: convertește orice text în secvențe de escape \uXXXX — forma pe care o folosesc șirurile JSON, JavaScript, Java și fișierele .properties atunci când este permis doar ASCII. Emoji-urile și alte caractere astrale devin perechi surogat.
🔒 Privat prin concepție: totul rulează în browserul tău pe acest dispozitiv. Datele tale introduse nu sunt încărcate niciodată pe un server.

Exemplu

Intrare:

café ☕

Ieșire:

caf\u00e9 \u2615

Despre acest convertizor

Secvențele de escape permit formatelor doar-ASCII să poarte orice caracter: fiecare caracter devine \u urmat de patru cifre hexazecimale ale punctului său de cod. Caracterele peste U+FFFF (majoritatea emoji-urilor) nu încap în patru cifre, așa că limbajele bazate pe UTF-16 le scriu ca pereche surogat — două escapări care împreună numesc un caracter — iar acest convertizor face același lucru, potrivindu-se cu ceea ce așteaptă parserele JSON și Java. Întâlnești acest format în fișiere .properties Java, încărcături JSON mai vechi de la servicii Java, exporturi de registru Windows și fișiere de internaționalizare unde un pipeline de build nu poate fi încredințat cu UTF-8 brut.

Întrebări frecvente

De ce un emoji a devenit două escape-uri?

Trăiește deasupra U+FFFF, așa că UTF-16 îl scrie ca pereche surogat: un surogat înalt (D800–DBFF) plus un surogat jos (DC00–DFFF). Analizatoarele le recombină automat.

Escape-ul \u este același lucru cu codificarea procentuală?

Nu — lumi diferite. \uXXXX aparține literalelor șir din cod și JSON; %XX aparține URL-urilor.

Ce caractere rămân neescapate?

ASCII-ul printabil simplu trece neatins (cu excepția barei oblice inverse și a ghilimelei, care sunt escapate ca rezultatul să rămână valid în interiorul unui șir).
