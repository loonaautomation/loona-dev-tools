ตัวสร้างแผนผังเว็บไซต์ XML - เปลี่ยนรายการ URL เป็น sitemap.xml ที่ถูกต้อง

สรุปสั้น ๆ: ตัวสร้างแผนผังเว็บไซต์ XML ใช้รายการ URL ธรรมดา - หนึ่งรายการต่อบรรทัด - และแสดง sitemap.xml ที่ถูกต้องพร้อมค่าเริ่มต้น lastmod, changefreq และ priority เพิ่มเติม โดย escape URL อย่างถูกต้องสำหรับ XML

คุณมีรายการ URL; การห่อ XML คือส่วนที่น่าเบื่อ วางรายการ ตั้งค่าเริ่มต้นครั้งเดียว และดาวน์โหลดแผนผังเว็บไซต์ที่เครื่องมือค้นหายอมรับ

เป็นส่วนตัวโดยการออกแบบ: ทุกอย่างในเครื่องมือนี้เกิดขึ้น 100% ในเบราว์เซอร์ของคุณด้วย JavaScript อินพุตของคุณไม่เคยถูกอัปโหลดไปยังเซิร์ฟเวอร์ ไม่เคยถูกจัดเก็บ และไม่เคยถูกเห็นโดยเรา - ปิดแท็บแล้วทุกอย่างหายไป

วิธีใช้ ตัวสร้างแผนผังเว็บไซต์ XML

  1. วาง URL ของคุณ หนึ่งรายการต่อบรรทัด หรือโหลดจากไฟล์ .txt
  2. ตั้งค่า lastmod, changefreq และ priority เริ่มต้นหากคุณต้องการให้พวกมันอยู่ในทุกรายการ
  3. คลิกสร้าง sitemap.xml
  4. ดาวน์โหลดไฟล์ วางมันไว้ที่รูตของไซต์ของคุณ และส่งมันใน Search Console และ Bing Webmaster Tools

วิธีการทำงาน

ตัวสร้างทำตามโปรโตคอล sitemaps.org: urlset ในเนมสเปซอย่างเป็นทางการ หนึ่งองค์ประกอบ url ต่อที่อยู่ และค่า loc ที่ทั้งปลอดภัยสำหรับ URL (ช่องว่างกลายเป็น %20) และ escape แบบ XML (& ใน query string กลายเป็น &amp; ซึ่งจำเป็น - & ดิบทำให้ไฟล์เป็น XML ที่ไม่ถูกต้อง) โปรโตคอลจำกัดแผนผังเว็บไซต์หนึ่งไว้ที่ 50,000 URL และ 50 MB; เครื่องมือนี้บังคับใช้ขีดจำกัด URL และบอกคุณเมื่อคุณชนมัน ณ จุดนั้นการเคลื่อนไหวที่ถูกต้องคือแผนผังเว็บไซต์หลายอันที่เชื่อมด้วยไฟล์ดัชนีแผนผังเว็บไซต์ โปรดทราบว่า Google ส่วนใหญ่เพิกเฉยต่อ changefreq และ priority แต่ lastmod ถูกใช้เมื่อมันแม่นยำ - ดังนั้นตั้งค่า lastmod ที่สะท้อนการเปลี่ยนแปลงจริงเท่านั้น

คำถามที่พบบ่อย

ตัวสร้างนี้ฟรีหรือไม่?

ใช่ - ฟรีทั้งหมด ไม่ต้องสมัครสมาชิก

แผนผังเว็บไซต์หนึ่งไฟล์เก็บ URL ได้กี่รายการ?

สูงสุด 50,000 ตามโปรโตคอลแผนผังเว็บไซต์ - และ 50 MB เมื่อไม่ได้บีบอัด ไซต์ที่ใหญ่กว่าใช้ดัชนีแผนผังเว็บไซต์ที่ชี้ไปยังแผนผังเว็บไซต์หลายไฟล์

Google ใช้ priority และ changefreq หรือไม่?

Google บอกว่ามันเพิกเฉยทั้งสองอย่างเป็นส่วนใหญ่ lastmod ถูกใช้เมื่อมันสะท้อนการเปลี่ยนแปลงจริงอย่างสม่ำเสมอ

ทำไม & จึงต้องกลายเป็น & ใน URL?

เพราะ sitemap.xml เป็น XML: เครื่องหมายแอมเพอร์แซนด์ดิบ ๆ จะเริ่มการอ้างอิง entity และทำให้เอกสารไม่ถูกต้อง ดังนั้นมันต้องถูก escape

มีอะไรถูกอัปโหลดหรือไม่?

ไม่ แผนผังเว็บไซต์ถูกสร้างในเบราว์เซอร์ของคุณ
