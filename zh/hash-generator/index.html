哈希生成器 - SHA-1、SHA-256、SHA-384 和 SHA-512

简而言之： 哈希生成器使用您浏览器内置的加密技术计算您文本的 SHA-1、SHA-256、SHA-384 和 SHA-512 摘要——与您的银行网站使用的相同的 Web Crypto 引擎。SHA-1 被诚实地标注：用于校验和，而非安全。

需要检查一个字符串的两个副本是否相同、生成一个破除缓存的指纹，或遵循一个要求 SHA-256 摘要的教程？粘贴文本，四个标准摘要会一起出现，随时可以复制。

注意：SHA-1 仅为校验和和遗留兼容性而包含——它 不 对于密码或安全来说并不安全。安全性方面请使用 SHA-256 或更强的算法，并为密码使用 bcrypt 或 Argon2 这样的适当密码哈希方案。

按设计保证隐私： 这个工具中的一切都 100% 在您的浏览器中使用 JavaScript 完成。您的输入从不上传到服务器，从不存储，我们也从不见过它——关闭标签，一切都消失了。

如何使用哈希生成器

  1. 输入或粘贴要哈希的文本。
  2. 点击“生成哈希”。
  3. 从结果中复制您需要的摘要。

它如何工作

加密哈希把任何输入变成一个固定长度的指纹。相同的输入总是给出相同的指纹；哪怕改动一个字符，指纹也会完全改变；而且无法从指纹重构出输入。本工具把您文本的 UTF-8 字节送入 Web Crypto API（crypto.subtle.digest）——这是浏览器原生、经过审计的加密功能，而不是 JavaScript 的重新实现。SHA-256 产生 64 个十六进制字符，SHA-512 产生 128 个，SHA-1 产生 40 个。SHA-1 的抗碰撞性已被攻破，因此它仅用于校验和以及仍要求它的遗留系统。

实例

用 SHA-256 对单词 "abc" 做哈希总是得到 ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad——这是全世界工程师用来检查哈希实现是否正确的已发布测试向量。在这里试一试并比较。

常见问题

这个哈希生成器免费吗？

是的——免费，无需注册，没有限制。

哈希和加密是一回事吗？

不是。哈希是单向的：它生成一个您可以比较的指纹，但您无法把它解密回原始文本。

为什么 SHA-1 被标为 "不用于安全"？

研究人员已经产生了真实的 SHA-1 碰撞，所以它不能用于保护密码、签名或证书。在不担心攻击的地方，它作为快速文件校验和仍然很好。

我应该用 SHA-256 哈希密码吗？

不直接。密码需要像 bcrypt、scrypt 或 Argon2 这样缓慢的、加盐的密码哈希函数——像 SHA-256 这样的快速哈希让攻击者每秒能猜测数十亿个密码。

我的文本会被上传去做哈希吗？

不会。哈希通过 Web Crypto 在您的浏览器中运行；您的文本从不离开您的设备。
