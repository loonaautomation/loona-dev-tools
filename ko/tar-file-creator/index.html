TAR 파일 생성기 - 파일로 .tar 아카이브 만들기

요약하면: TAR 파일 생성기는 브라우저의 사양에 맞는 ustar 작성기를 사용해 모든 파일 집합을 단일 표준 .tar 아카이브로 묶어요 - 파일을 추가하고, 선택적으로 폴더에 그룹화하고, 다운로드하세요.

TAR은 여전히 Linux, 서버, 백업의 공용어예요 - 하지만 타르볼을 만들어야 하는 Windows 사용자는 보통 먼저 무언가를 설치해야 해요. 이 페이지는 브라우저에서 진짜 TAR 아카이브를 써요: 적절한 ustar 헤더, 체크섬, 타임스탬프, 업로드 없이 기기에서 만들어져요.

여기에 파일을 놓으세요 또는 클릭해 기기에서 파일을 선택하세요
파일 이름크기

기억하세요: TAR은 압축하지 않아요. .tar는 추가된 모든 파일을 합친 크기 정도가 돼요(512바이트 블록으로 올림돼요). 더 작게 필요해요? 이후에 결과를 GZIP 압축기로 돌리거나, 대신 ZIP 파일 만들기를 사용하세요.

설계상 비공개: 이 도구의 모든 것은 JavaScript로 브라우저에서 100% 일어나요. 파일은 서버에 절대 업로드되지 않고, 절대 저장되지 않으며, 저희가 절대 보지 않아요 - 탭을 닫으면 모든 것이 사라져요. 정직한 제한 하나: 변환은 기기 메모리에서 일어나, 매우 큰 아카이브(수백 메가바이트)는 메모리가 적은 휴대폰에서 느리거나 실패할 수 있어요.

TAR 파일 생성기 사용법

  1. 파일을 위 상자에 놓거나, 클릭해 기기에서 파일을 고르세요. 여러 차례에 나누어 파일을 추가할 수 있어요.
  2. 목록을 확인하세요 - 실수로 추가한 것은 제거하고, 전체 크기를 살펴보세요.
  3. 모든 파일이 아카이브 안의 한 폴더 안에 있도록 선택적으로 폴더 이름을 입력하고, TAR에 이름을 지어주세요.
  4. TAR 만들기 & 다운로드를 클릭하세요. .tar는 Linux/macOS에서 tar로, Windows에서 7-Zip이나 WinRAR로 열려요.

작동 방식

TAR 아카이브는 레코드의 스트림이에요: 각 파일마다 512-byte ustar 헤더 블록(파일 이름, 팔진수 크기, 수정 시간, 헤더 자체의 체크섬, 'ustar' 매직, 그리고 경로가 100자를 넘게 이어지게 하는 prefix 필드 - 그보다 더 긴 경로에는 GNU longname 항목)이 있고, 그 뒤에 512-byte 블록의 정수 배로 채워진 파일 내용이 와요. 제로 블록 두 개가 아카이브를 닫아요. 이 페이지는 그 형식을 직접 구현해요 - 라이브러리 없음, 서버 없음 - 그리고 작성기는 Python의 tarfile 모듈이 그 출력을 바이트 단위로 다시 읽는 것으로 검증됐어요. TAR는 파일을 압축하지 않고 저장하므로 아카이브는 부분들의 합이에요; 압축은 별도 단계예요(.tar.gz가 더하는 것이 바로 그것이에요).

풀이된 예시

파일 세 개를 추가해요: deploy.sh(1 KB), config.yml(3 KB), logo.png(48 KB), 폴더 이름은 'release'로 설정돼요. 도구는 release.tar - 또는 선택한 이름 - 를 만들어요. 세 파일이 모두 들어 있는 release 폴더를 담고, 각각 실제 수정 시간을 유지해요. 52 KB 콘텐츠에서 TAR은 약 54 KB로 나와요: 파일 자체, 헤더 세 개, 패딩, 압축 없음 - Linux에서 tar가 만들 바로 그것이에요.

자주 묻는 질문

이 TAR 파일 생성기는 무료인가요?

네 - 무료, 회원가입 없음, 제한 없음, 워터마크 없음이에요.

파일이 서버에 업로드되나요?

아니요. TAR는 기기에서 브라우저에서 실행되는 JavaScript가 써요. 파일은 절대 떠나지 않아요.

TAR이 왜 파일과 같은 크기인가요 - 또는 약간 더 큰가요?

TAR은 아무것도 압축하지 않아요; 묶기만 해요. 각 파일은 또한 512바이트 헤더를 추가하고 512바이트 경계까지 패딩돼, 아카이브는 원시 총합보다 약간 더 커요. 압축된 타르볼에는, 여기서 TAR을 만든 뒤 GZIP 압축기로 돌리세요 - 말 그대로 .tar.gz가 만들어지는 방법이에요.

Linux와 GNU tar가 여기서 만든 아카이브를 받아들일까요?

네. 작성기는 ustar 사양을 따라요 - 올바른 팔진수 필드와 헤더 체크섬, ustar 매직, 긴 경로를 위한 접두사 분할, 매우 긴 경로를 위한 GNU longname 항목 - 그리고 출력은 테스트 중에 Python의 tarfile 모듈로 다시 읽어 검증됐어요.

기존 TAR에 파일을 추가하거나 .tar.gz를 직접 만들 수 있나요?

이 도구에서는 아니에요 - 매번 새 아카이브를 만들어요. 기존 ZIP을 한 단계로 .tar.gz로 바꾸려면 ZIP을 TAR.GZ로 변환하는 도구를 사용하세요; 이 TAR를 .tar.gz로 압축하려면 나중에 GZIP 압축기를 사용하고 결과 이름을 .tar.gz로 바꾸세요.
